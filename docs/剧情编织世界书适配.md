# 剧情编织·世界书剧情适配说明

## 详细版补全（2026-10-19）

- **原文不再只取 `详细剧情`**：每段 `原文内容` 尽量回填原世界书完整 `<章节剧情>`，包含 `<事件一>` 到 `<事件四>` 等事件正文。
- **概括不再漏事件**：`本段概括` 会在原详细剧情后追加 `关键事件：`，逐条列出事件名与事件说明；`模拟宇宙·始发测试` 现在能直接看到事件一至事件四。
- **超长段拆分**：原文超过 6000 字的分段按 `<事件N>` 边界拆分，事件本身过长再按段落拆；拆分后单段原文最长约 6000 字。拆分件保留原段 id 作为第一件，后续件使用 `__partN`，进度仍映射到第一件。
- **运行时注入原文**：当前段的 `原文内容` 会作为「当前段完整剧情参考（原世界书）」注入，最多 8000 字；前一段/下一段仍只注入摘要，避免上下文爆炸。
- 原始 332 个 `story:` 条目经拆分后为 **375 个分段**；系列数仍为 29。

## 一、这次做了什么

把 `崩坏 星穹铁道  银河球棒侠传说.json` 世界书里的 **332 个 `story:` 条目**，适配成《开拓轶事》剧情编织格式：

- **29 个剧情系列**：主线 23 个 + 支线/同行/常驻/续闻/模拟宇宙/活动 6 个。
- **332 个分段**：一个世界书剧情条目 = 一个章节 = 一个分段（每段 1 章）。
- **总文本约 12.4 MB**：含章节原文、事件、角色/势力/地点档案，可直接离线使用。
- 交付文件：`开拓轶事/kaituo-剧情-世界书版.json`（完整系统备份，可直接导入）。
- 内置资源：`public/data/story-weaving-canon/wb_*.json`（29 个文件，启动时随内置原著一起加载）。

## 四、在游戏里怎么用

1. 打开「剧情编织」面板。
2. 顶部有三个轨道页签：**原著剧情 / 世界书剧情 / 自制剧情**。
3. 点「世界书剧情」，会看到 29 个系列卡片；用分类按钮（全部/主线/支线/同行/常驻/活动/模拟宇宙/续闻）和搜索框（系列 / 章节 / 角色 / 地点 / 版本）查找。
4. 展开系列，点某个分段，再点「设为当前」，该段就会成为主注入段。
5. 主线系列按“前一段 / 当前段 / 下一段”滑窗注入；支线/同行/常驻/活动/模拟宇宙/续闻是**独立单段**，只注入当前任务，不会把相邻任务带进上下文，也不会自动跳到下一项任务。
6. 想导出：面板里的「导出世界书」会导出世界书轨道 JSON；「导出全部备份」会导出全部三条轨道。

### 手动暂停与「已经历」锁定

- 剧情注入的开关只由系列卡片上的「暂停注入 / 启用注入」手动控制。
- 暂停后不再调用 AI 进行剧情推进判定（含逐回合判定、对齐巡检和 `<剧情推进>` 申报），也不会注入剧情素材。
- 再次开启后，不会立刻拿暂停前的旧正文判定；要等下一段新正文生成后，才清除“等待新正文”标记并恢复判定。
- 标记为「已经历」的分段会被 AI 锁定：AI 推进判定不能把它改回当前/未开始/已跳过/已偏离；AI 分解与批量分解也会跳过它。需要调整时，只能在分段详情里手动编辑并保存。

## 六、已知取舍

- 世界书条目是**剧情概要 + 事件结构**，不是游戏原文；`原文内容` 保留的是世界书结构化文本，用于在面板里重新 AI 分解或查阅，不会整段注入正文。
- 支线合集把 160 个独立任务放在一个系列里，靠分类、地区、搜索和“单段注入”管理；不会按顺序自动推进。
- 世界书里没有明确角色名的短支线，`登场角色` 至少保留“开拓者”，避免空白。
- 星神等宇宙级存在会出现在 `登场角色`/档案里，但不会进入 `角色推进`，避免把“瞥视”误写成常规角色行动。
- 旧的原著 27 个系列仍保留；如果想让世界书成为新开局的默认主轨，需要在「世界书剧情」里手动设为当前，或后续再做“默认剧情源”设置。
